## 2. 參考站的取捨

Mel One Renovations 的可借鑑之處是清楚的首屏定位、服務導覽、工程證據、詢價步驟、公司資料、FAQ 和完整頁腳。Sydney Carpentry 不直接套用該站較硬的黑橘視覺、Brisbane 服務文案、電話、地址、案例或排名說法。外部木工與圍欄站只用於觀察問題分類及詢價流程，不複製圖片、評論、保險、年資或文案。

已選定「柔和木作現場」而非輕量換皮或 Renovations 版式移植。採暖米白、低飽和灰綠、柔和深藍、克制木色；更明顯的圓角與有節奏的圖片大小，避免整站是同一種矩形卡片。實拍照片像可閱讀的工作記錄，而不是裝飾圖牆。

## 3. 視覺與共用介面

CSS 由 public/site.css 的單一 token 系統負責；更新 DESIGN.md 時須同步修改實際 token，不另建互相衝突的主題。

| 角色 | 建議 token | 用途 |
|---|---|---|
| 深藍墨色 | #20343D | 主要文字、頁眉、少數深底 |
| 暖米白 | #F7F6F1 | 網站背景 |
| 白色 | #FFFEFB | 內容表面 |
| 霧灰綠 | #DFE9E1 | 輕襯底、區塊層次 |
| 木色 | #CC955F | 主操作和少量引導；深藍墨色文字搭配時須達一般文字對比要求 |
| 深木色 | #74491F | 白底上的重點文字 |

卡片圓角約 28–32px，主圖及詢價帶約 32–36px，表單欄位約 14–16px，主要按鈕為膠囊形。以留白、尺寸與照片組合建立層次，少用硬分隔線；不讓所有元素都變成同尺寸膠囊。短英文 display 標題採 Fraunces、英文正文採 Manrope；中文大標題採 Noto Serif SC、中文正文採 Noto Sans SC。字體資產須確認授權後自託管，並有相容 fallback、最小必要字重及避免載入跳動的設定。精確字重及色彩要以桌面／手機實際畫面和對比度驗證。

首頁保留目前生成的工作場景圖作氛圍圖，不冒充 Mel One 完工案例；另外提高業主實拍的工作記錄能見度。服務圖只有在對應服務缺乏實拍時作視覺補充。所有原有資產路徑保持可用；要改圖尺寸可新增衍生檔，但不覆蓋原始 JPEG/WebP。

共用頁眉保留 logo、九項服務分組、真實工作、Areas、About、EN/中文對等切換與明確電話／詢價入口。桌面與手機都要讓重要連結可用，手機選單可用鍵盤操作。首頁依「做甚麼 → 選服務 → 真實工作 → 地區 → 詢價」順序排版。頁腳為品牌聯絡、九項服務、地區入口、公司／隱私四組；手機自然重排。頁腳不塞滿 56 個地名，需有通往完整 Areas 頁和代表性區域的可抓取連結。

已查閱本地媒體清單、建站交付文件及較早任務記錄：它們把五組照片映射到服務，沒有逐張 suburb、完成結果或可信 Before/After 配對。若日後獲得工單或業主逐組確認，可追加地點／結果及前後次序；在此之前標題和說明只描述可見的現場、細節與工作階段，不以生成圖或未核對照片偽造前後對比。每張公開相片檢查隱私和權利；現有被排除的帶鑰匙、人物反光、私人獎盃照片不因改版自動公開。

## 5. 56 個 suburb 同批內容模型

保留 /areas/<suburb>/ 與 /zh/areas/<suburb>/ 的獨立路由。現有每頁各有一條詢價情境，但多數段落共用骨架；這不足以直接宣稱 56 頁都已有強烈的本地價值。一次上線的前提是 56 頁都經逐頁內容驗收，不以地名替換、機械生成或假的當地案例湊數。

每個 suburb 頁須有清楚的地區名、本站實際可接的木工需求、與該頁相符的服務 Owner 連結、現場照片該怎麼拍、涉及訪客的報價／進場問題、附近或所屬區域的有用導航、對應語言入口和可用詢價方式。另為每頁記錄一項與該 suburb 實際相關、可核實的客戶需要或服務事實、其來源以及它為何值得獨立頁面；若僅能把同一段文字換地名，不能通過內容門檻。可核實的地區特徵來自可靠資料並記錄來源；服務可承接及真實工程事實以業主提供資料為準。沒有核實的工程地點就只連到相關服務的真實工作記錄，不稱為該 suburb 的案例。所有區頁的標題、主要段落和問題解答須按當地客戶任務編寫並人工查重，不能只是相同內容替換地名。若 56 頁中任一頁未通過，按業主同批上線決定，整批標為未備妥並回報具體待補資料，不私自改為分批上線。

Areas 總頁完整列出 56 區，按易讀區組查找。所有 56 區都可接木工詢盤，但具體工作、交通、現場通道及排期仍需確認；不創造街道辦公室、到場時間保證或未授權的工種。結構化資料僅聲明已核實的服務與地區關係，不把「可詢問」擴寫成每項服務在每區都必接。

Privacy 須描述網站真實表單資料流：電話或電郵、suburb、問題描述、可選照片與必要的詢價來源資料；現有表單沒有姓名欄位，不把它寫成已收集資料。頁面還須說明用途、授權接觸資料的人員、私有儲存和照片權限、通知服務、查詢／更正／刪除方式以及聯絡方法。現有 Worker 用 D1 保存已接納詢盤、R2 私有保存照片、通知失敗可重試，未設定自動保留期限，也未接入正式收件端。故公開的 Privacy 不得杜撰保留天數或宣稱實際收件已驗證；正式上線前須由業主批准資料保留／刪除政策、處理者及真實收件路由，並讓頁面與運行設定一致。英文及中文 Privacy 均是完整可索引頁。

生產 Organization / WebSite / Service 結構化資料與頁面正文使用同一事實來源。Organization 可列 legalName、taxID、品牌、實際聯絡方式及經確認的服務地區；Service 節點只列批准的 Owner 與適用區域。沒有經核實的悉尼地址、GBP、星級或評論就不寫入 schema。
